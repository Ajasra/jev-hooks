# Documentation

1. Inspect the document's reader, purpose, existing layout, and actual behavior.
   Preserve repository conventions and the author's voice.
2. Lead with what the reader needs to do or understand. Keep operational examples
   near instructions; link detailed contracts and background instead of duplicating them.
3. Make targeted edits within the request. Use headings and lists when useful,
   without mandatory document anatomy, line quotas, screenshots, or shell wrappers.
4. Verify affected commands, links, and factual claims as appropriate. Do not run
   runtime suites or a second editing workflow for a small prose change.
5. Deliver the document and concise verification evidence.

For JEV, use [documentation conventions](../../protocols/documentation-standard-protocol.md).
For Vasily-authored prose, the [voice profile](../../protocols/style-protocol.md) is
optional guidance. An explicit deslop request uses the
[canonical editor](../../../../global-skills/skills/fuck-slop/SKILL.md); ordinary docs
work incorporates clear writing directly without loading all editing references.
